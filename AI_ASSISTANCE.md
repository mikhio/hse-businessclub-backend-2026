# Использование ИИ и проверки

Для проектирования, реализации и проверки использовался Codex. Ниже описаны задачи, исправления и результаты проверок.

## Что поручили ИИ

- Декомпозировать исходное задание: модель гостя и журнала, подпись пропуска, Telegram-обработчики, API, контейнерный запуск.
- Реализовать код на Python с PostgreSQL и aiogram, тесты и документацию.
- Проверить гонки и права доступа, передать готовое решение на независимое ревью.

## Что исправлено по проверкам

1. Первый вариант распознавания использовал только ZXing `LocalAverage`. PNG распознавался, но два теста с JPEG качества 70 завершились ошибкой «QR не найден». Диагностика того же изображения показала успешное чтение с `GlobalHistogram`. В итоге используются оба метода и объединяются найденные значения, чтобы одновременно обнаруживать несколько QR. Повторная проверка проходит для PNG, сжатого JPEG и его поворота.
2. Первоначальный транспорт API предполагал общий bearer API-ключ и ID организатора в теле запроса. Для ясной границы доступа он заменён credentials, привязанными к конкретному Telegram ID; мастер-секрет как bearer больше не принимается. Проверяются подмена `organizer_id` в теле, подмена ID в заголовке, регистрация от чужого имени и получение чужого QR. Бот выводит credentials только из настоящего отправителя aiogram update.
3. Одноразовость реализована ограничением PostgreSQL и атомарным `INSERT ... ON CONFLICT DO NOTHING`, а не предварительным `SELECT`. Проверка 16 параллельных вызовов подтверждает одну запись и одно начисление.

## Выполненные проверки

- `ruff check app scripts tests` — успешно.
- Полный `python -m pytest -q` с реальным PostgreSQL 16: **24 passed**, локально Python 3.13 — 11,55 секунды; в Docker Python 3.12 — 16,88 секунды. Это время конкретных прогонов, не гарантия скорости на другой машине.
- В контейнерном прогоне нет пропущенных тестов. Единственное предупреждение Starlette касается будущей замены httpx в TestClient; в этих прогонах транспорт отработал успешно.
- Compose собран и запущен: API и PostgreSQL healthy, `/health` отвечает HTTP 200.
- `scripts.demo` против работающего HTTP API: изображение распознано; первый чек-ин начисляет 10 демонстрационных баллов, второй — нет; в журнале одна запись. Имя и Telegram ID этой проверки вымышленные, сообщения реальным пользователям не отправляются.
- API перезапущен отдельной командой; в проверке сохранения сопоставлены UUID гостя и подписанный пропуск до/после перезапуска. Результат совпал.
- Telegram-сценарий проверен настоящим aiogram Dispatcher и настоящими обработчиками с PostgreSQL и HTTP ASGI API. Только сетевой транспорт Telegram заменён тестовым: он выдаёт скачиваемое JPEG и принимает исходящие вызовы. Это подтверждает путь обработки, но не реальную доставку в Telegram.

## Использованные технические источники

- [Telegram Bot API](https://core.telegram.org/bots/api) — фото, скачивание файлов, callback-запросы.
- [aiogram: загрузка файлов](https://docs.aiogram.dev/en/latest/api/download_file.html) — интерфейс скачивания через Bot.
- [ZXing-C++ Python wrapper](https://github.com/zxing-cpp/zxing-cpp/blob/master/wrappers/python/README.md) — чтение QR из изображений. Параметры binarizer дополнительно проверены по docstring установленного модуля.
- [SQLAlchemy PostgreSQL: ON CONFLICT](https://docs.sqlalchemy.org/en/20/dialects/postgresql.html#insert-on-conflict-upsert) и [PostgreSQL INSERT](https://www.postgresql.org/docs/current/sql-insert.html) — атомарная вставка при конфликте уникальности.
